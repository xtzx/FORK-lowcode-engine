# 🎨 __createVirtualDom 函数执行流程详解

## 一、函数概览

### 1.1 核心职责

**`__createVirtualDom` 是整个渲染器的核心引擎**，负责递归地将 Schema 结构转换为 React 虚拟 DOM。

### 1.2 函数签名

```typescript
__createVirtualDom = (
  originalSchema: IPublicTypeNodeData | IPublicTypeNodeData[] | undefined,
  originalScope: any,
  parentInfo: INodeInfo,
  idx: string | number = '',
): any
```

**参数说明：**

| 参数 | 类型 | 说明 |
|------|------|------|
| `originalSchema` | `Schema \| Schema[] \| undefined` | Schema 数据（可以是对象、数组、表达式） |
| `originalScope` | `any` | 作用域对象（包含 props、state、this 等） |
| `parentInfo` | `INodeInfo` | 父组件信息（schema + Comp） |
| `idx` | `string \| number` | 循环索引（用于生成 key） |

**返回值：**
- React 元素（单个或数组）
- `null`（不渲染）
- 基础类型（string、number）

### 📋 阶段 6：Scope 生成（Line 1476-1502）

```typescript
let scopeKey = '';
if (Comp.generateScope) {
  const key = this.__parseExpression(schema.props?.key, scope);

  if (key) {
    scopeKey = key;  // 使用自定义 key
  } else if (!schema.__ctx) {
    schema.__ctx = { lceKey: `lce${++scopeIdx}` };
    scopeKey = schema.__ctx.lceKey;
  } else {
    scopeKey = schema.__ctx.lceKey + (idx !== undefined ? `_${idx}` : '');
  }

  if (!this.__compScopes[scopeKey]) {
    this.__compScopes[scopeKey] = Comp.generateScope(this, schema);
  }
}

// 创建新的 scope 上下文
if (scopeKey && this.__compScopes[scopeKey]) {
  const compSelf = { ...this.__compScopes[scopeKey] };
  compSelf.__proto__ = scope;
  scope = compSelf;
}
```

**执行流程：**
```
判断组件是否有 generateScope 方法
  ├─ 没有 → 跳过
  └─ 有 → 生成 scopeKey
           ↓
           生成策略：
           1. 优先使用 schema.props.key
           2. 没有则生成 lceKey（lce1, lce2...）
           3. 循环场景追加索引（lce1_0, lce1_1...）
           ↓
           检查缓存：this.__compScopes[scopeKey]
           ├─ 有 → 使用缓存
           └─ 没有 → 调用 Comp.generateScope() 生成
           ↓
           创建新 scope，原型链指向父 scope
           scope = { ...newScope, __proto__: oldScope }
```

**Scope 链示例：**
```
根 scope = {
  props: {...},
  __proto__: rendererInstance
}
  ↓
子组件 scope = {
  ...compScope,
  __proto__: 根 scope
}
```

```mermaid
graph TD
    Start([__createVirtualDom 开始]) --> Check1{schema === null/undefined?}
    Check1 -->|是| Return1[返回 null]
    Check1 -->|否| Check2{engine 存在?}

    Check2 -->|否| Return2[返回 null]
    Check2 -->|是| Try[try 块开始]

    Try --> Special[特殊类型处理]

    Special --> JSExpr{JSExpression?}
    JSExpr -->|是| ParseExpr[__parseExpression]
    ParseExpr --> ReturnExpr[返回表达式结果]

    JSExpr -->|否| I18n{i18n 数据?}
    I18n -->|是| ParseI18n[parseI18n]
    ParseI18n --> ReturnI18n[返回翻译文本]

    I18n -->|否| Slot{JSSlot?}
    Slot -->|是| RecursiveSlot[递归处理 slot.value]
    RecursiveSlot --> ReturnSlot[返回插槽内容]

    Slot -->|否| Basic[基础类型处理]

    Basic --> String{string?}
    String -->|是| ReturnString[返回字符串]

    String -->|否| Number{number/boolean?}
    Number -->|是| ToString[转换为字符串]
    ToString --> ReturnNumber[返回转换结果]

    Number -->|否| Array{Array?}
    Array -->|是| ArrayLen{length === 1?}
    ArrayLen -->|是| ArraySingle[递归处理单个元素]
    ArrayLen -->|否| ArrayMap[map 递归处理每个元素]
    ArrayMap --> ReturnArray[返回元素数组]

    Array -->|否| React{$$typeof 存在?}
    React -->|是| ReturnReact[返回 React 元素]

    React -->|否| Fragment{Fragment?}
    Fragment -->|是| UnpackFrag[解包子节点]
    UnpackFrag --> RecursiveFrag[递归渲染子节点]

    Fragment -->|否| Text{Text?}
    Text -->|是| ConvertText[props.text → children]

    Text -->|否| ValidSchema{isSchema?}
    ValidSchema -->|否| Return3[返回 null]
    ValidSchema -->|是| FindComp[查找组件]

    FindComp --> CompFound{Comp 找到?}
    CompFound -->|否| NotFound[渲染 NotFoundComponent]
    NotFound --> ReturnNotFound[返回占位组件]

    CompFound -->|是| Loop{schema.loop 存在?}
    Loop -->|是| ParseLoop[解析 loop 数据]
    ParseLoop --> UseLoop{isUseLoop?}
    UseLoop -->|是| LoopRender[__createLoopVirtualDom]
    LoopRender --> ReturnLoop[返回循环渲染结果]

    UseLoop -->|否| Condition[解析 condition]
    Loop -->|否| Condition

    Condition --> CondCheck{condition 满足?}
    CondCheck -->|否| DesignCheck{设计态?}
    DesignCheck -->|否| Return4[返回 null]
    DesignCheck -->|是| Scope[Scope 生成]
    CondCheck -->|是| Scope

    Scope --> GenScope{Comp.generateScope?}
    GenScope -->|是| GenScopeKey[生成 scopeKey]
    GenScopeKey --> CreateScope[创建新 scope]
    GenScope -->|否| Props[Props 准备]
    CreateScope --> Props

    Props --> DesignProps[添加 __designMode, __tag]
    DesignProps --> GetProps[__getComponentProps]
    GetProps --> HOC[应用 HOC]

    HOC --> LeafHOC[leafWrapper 设计态]
    LeafHOC --> CompHOC[compWrapper 错误边界]
    CompHOC --> Ref[Ref 收集]

    Ref --> RefStore[this.$\(\) 存储]
    RefStore --> RefNotify[engine.onCompGetRef 通知]
    RefNotify --> Key[Key 生成]

    Key --> KeyPriority{优先级判断}
    KeyPriority --> KeyCustom[1. props.key]
    KeyPriority --> KeyLce[2. lceKey]

    KeyPriority --> KeyId[4. schema.id]
```

## 四、核心知识点总结

### 4.1 类型处理优先级

```
1. null/undefined → 返回 null
2. JSExpression → 执行表达式
3. i18n 数据 → 翻译
4. JSSlot → 递归渲染插槽
5. string → 直接返回
6. number/boolean → 转字符串
7. Array → 递归处理每个元素
8. React 元素 → 直接返回
9. Fragment → 解包
10. Text → 转换格式
11. 正常组件 → 完整渲染流程
```

### 4.2 条件渲染逻辑

| condition | designMode | 是否渲染 |
|-----------|-----------|---------|
| `true` | 任意 | ✅ |
| `false` | `'design'` | ✅（强制） |
| `false` | 其他 | ❌ |
| `undefined` | 任意 | ✅（默认 true） |

### 4.3 Key 生成策略

```
优先级：
props.key > lceKey > idx > schema.id

示例：
普通组件: 'lce1_0_' 或 'node_123'
循环组件: 'lce2_0_0', 'lce2_0_1'
```

### 4.4 Scope 链设计

```javascript
childScope = {
  ...compScope,
  __proto__: parentScope
}

访问变量时：
1. 先查找 childScope
2. 没有则查找 parentScope
3. 没有则查找 rendererInstance
```

### 4.5 HOC 包装顺序

```
原组件
  ↓ leafWrapper（设计态）
LeafWrapper
  ↓ compWrapper（错误边界）
ErrorBoundary(LeafWrapper(原组件))
```

## 六、常见陷阱与注意事项

### ⚠️ 陷阱 1：作用域污染

```typescript
let scope = originalScope;  // ✅ 使用 let，可能被修改

// 错误写法：
const scope = originalScope;  // ❌ 使用 const，无法修改
```

### ⚠️ 陷阱 2：循环中的 key

```typescript
// ✅ 正确：检查是否有 lceKey
(item as IPublicTypeNodeSchema)?.__ctx?.lceKey ? '' : String(idy)

// ❌ 错误：直接使用索引
String(idy)  // 可能导致 key 冲突
```

### ⚠️ 陷阱 3：设计态强制渲染

```typescript
if (!condition && !displayInHook) {
  return null;
}
```

**设计态下即使 condition=false 也要渲染，否则无法编辑**
